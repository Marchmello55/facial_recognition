# Переход на SQLite в системе распознавания лиц

## Что такое .pkl и почему мы перешли на SQLite

### Расширение .pkl
**Pickle (.pkl)** - это бинарный формат сериализации данных в Python. Он позволяет сохранять любые Python-объекты (словари, списки, numpy массивы) в файл и загружать их обратно.

**Проблемы .pkl для хранения лиц:**
1. ❌ **Нет проверки целостности** - если файл поврежден, все данные теряются
2. ❌ **Нет атомарных операций** - при сбое во время записи файл может повредиться
3. ❌ **Невозможность частичного чтения** - нужно загружать весь файл целиком
4. ❌ **Нет транзакций** - нельзя откатить изменения при ошибке
5. ❌ **Проблемы с версиями** - разные версии библиотек могут создавать несовместимые форматы
6. ❌ **Конфликты размеров векторов** - как в вашей ошибке: `shapes (313,) and (327,) not aligned`

### Преимущества SQLite

**SQLite** - это легковесная реляционная база данных, которая хранится в одном файле.

**Преимущества для нашей системы:**

| Характеристика | .pkl файл | SQLite |
|---------------|-----------|--------|
| Целостность данных | ❌ Нет гарантий | ✅ ACID транзакции |
| Проверка схемы | ❌ Нет | ✅ Типы данных и ограничения |
| Частичное чтение | ❌ Весь файл | ✅ Только нужные записи |
| Индексы | ❌ Нет | ✅ Быстрый поиск по имени |
| Одновременный доступ | ❌ Проблемы | ✅ Блокировки на уровне записей |
| Откат изменений | ❌ Невозможно | ✅ Транзакции ROLLBACK |
| Размер вектора | ❌ Любая ошибка | ✅ Валидация при вставке |
| История добавления | ❌ Нет | ✅ TIMESTAMP автоматически |

## Как работает новая система

### Структура таблицы

```sql
CREATE TABLE faces (
    id INTEGER PRIMARY KEY AUTOINCREMENT,      -- Уникальный ID
    name TEXT NOT NULL UNIQUE,                 -- Имя человека (уникальное)
    encoding BLOB NOT NULL,                    -- Вектор признаков (128 float)
    added_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP -- Дата добавления
)
```

### Хранение векторов лиц

Вектор лица (128 чисел float) сериализуется через `pickle` и сохраняется как BLOB:

```python
# Сохранение
encoding_blob = pickle.dumps(encoding)  # numpy array -> bytes
cursor.execute("INSERT INTO faces VALUES (?, ?, ?)", (name, encoding_blob))

# Загрузка
encoding = pickle.loads(encoding_blob)  # bytes -> numpy array
```

### Автоматическая валидация

При загрузке базы проверяется каждый вектор:

```python
if isinstance(encoding, np.ndarray) and len(encoding) == 128:
    # Вектор корректен, добавляем в память
    self.known_faces.append(encoding)
else:
    # Вектор поврежден, пропускаем с предупреждением
    print(f"⚠️ Пропущено поврежденное лицо '{name}'")
```

Это решает вашу проблему с разными размерами векторов!

## Миграция данных

Старый файл `.pkl` больше не используется. При первом запуске с новой версией:

1. Старый файл `face_database.pkl` игнорируется
2. Создается новый файл `faces.db` (SQLite)
3. База начинается пустой - нужно добавить лица заново

**Рекомендация:** Удалите старый файл:
```bash
rm face_database.pkl
```

## Использование

Все команды в меню работают так же:

```
1. Запустить распознавание с веб-камеры
2. Добавить лицо из файла изображения  
3. Показать список всех лиц в базе
4. Удалить лицо из базы
5. Очистить всю базу данных
6. Выход
```

Но теперь:
- ✅ Данные защищены от повреждения
- ✅ Автоматическая проверка размера векторов
- ✅ Уникальность имен гарантирована СУБД
- ✅ Можно добавлять метаданные (дата, путь к фото и т.д.)

## Технические детали

### Почему не PostgreSQL/MySQL?

Для локальной системы распознавания лиц SQLite идеален:
- Не требует установки сервера
- Один файл вместо множества
- Встроен в Python (`import sqlite3`)
- Достаточно быстр для тысяч записей
- Кроссплатформенный

### Формат векторов

Современная библиотека `face_recognition` использует модель ResNet-34, которая создает векторы размером **128 float**. Это стандарт индустрии.

Раньше вы столкнулись с ошибкой, потому что:
- Либо использовалась старая версия модели (другой размер)
- Либо данные в .pkl повредились
- Либо смешались векторы от разных моделей

SQLite с проверкой `len(encoding) == 128` предотвращает эту проблему.

## Заключение

Переход на SQLite делает систему:
- **Надежнее** - защита от повреждения данных
- **Стабильнее** - нет ошибок с размерами векторов
- **Расширяемее** - легко добавить новые поля (путь к фото, дата, заметки)
- **Профессиональнее** - используется правильная технология для хранения данных
